# Microsoft SQL Server и работа с данными

## Что такое SQL Server

Microsoft SQL Server — реляционная система управления базами данных (СУБД), разработанная Microsoft. Она предназначена для создания и хранения баз данных, выполнения запросов, управления данными, обеспечения их целостности, безопасности и управления доступом пользователей.

В этой работе рассматривается реляционная база CollegeDB и операции с её структурой и данными.

---

## Database Engine

Database Engine — основной компонент SQL Server, который отвечает за хранение, обработку и управление реляционными данными. Именно он выполняет операции с таблицами, индексами, ключами, транзакциями и запросами к данным.

По сути, SSMS используется как инструмент работы пользователя, а фактические операции с базой выполняет Database Engine.

---

## SSMS (SQL Server Management Studio)

SQL Server Management Studio — графический клиентский инструмент для администрирования SQL Server. Через SSMS можно подключаться к SQL Server, создавать базы и объекты, выполнять SQL-запросы и управлять данными.

Важно различать роли: SSMS — клиентский инструмент, SQL Server — серверная СУБД, Database Engine — основной компонент SQL Server, выполняющий операции с данными.

---

## Иерархия объектов

Иерархия SQL Server строится по вложенным уровням:

- Экземпляр SQL Server (Instance) содержит несколько баз данных
- База данных содержит схемы (Schemas)
- Схемы содержат объекты: таблицы, представления, хранимые процедуры и функции

Таким образом: Instance → Database → Schema → объекты базы данных.

---

## SQL и T-SQL

**SQL (Structured Query Language)** — язык структурированных запросов, используемый для работы с реляционными данными.

**Transact-SQL (T-SQL)** — расширение SQL, используемое Microsoft SQL Server. T-SQL дополнительно предоставляет программные возможности: переменные, условные конструкции, циклы, обработку ошибок, хранимые процедуры и другие средства управления.

---

## Группы SQL-команд

**DDL (Data Definition Language)** — определяет и изменяет структуру базы данных. Основные команды: CREATE, ALTER, DROP.

**DML (Data Manipulation Language)** — изменяет данные в таблицах. Основные команды: INSERT, UPDATE, DELETE.

**DQL (Data Query Language)** — используется для получения данных. Основная команда: SELECT.

**DCL (Data Control Language)** — управляет правами доступа. Основные команды: GRANT, DENY, REVOKE.

**TCL (Transaction Control Language)** — управляет транзакциями. Основные команды: BEGIN TRANSACTION, COMMIT, ROLLBACK.

---

## Типы данных

Тип данных определяет, какие значения может хранить столбец и каким образом SQL Server должен их обрабатывать. Тип выбирают по смыслу данных, допустимому диапазону и требованиям к точности. Неправильный тип может привести к ошибкам при сохранении, потере точности или излишнему расходу памяти.

Основные типы данных:

- **INT** — целые числа и идентификаторы
- **DECIMAL** — точные числа, например денежные значения
- **NVARCHAR** — текстовые строки, в том числе на русском языке
- **DATE** — дата без времени
- **TIME** — время без даты
- **DATETIME2** — дата и время
- **BIT** — значение "да/нет"

---

## NULL, 0 и пустая строка

NULL означает отсутствие значения: значение отсутствует или неизвестно.

0 — это конкретное числовое значение.

'' — это пустая строка, то есть конкретное строковое значение длины 0.

По сути, NULL нельзя считать синонимом нуля или пустой строки.

---

## Ограничения таблицы

Ограничение — правило, которое определяет, какие данные можно записать в таблицу.

- **NOT NULL** — делает значение обязательным
- **PRIMARY KEY** — задаёт уникальный идентификатор строки
- **FOREIGN KEY** — связывает таблицы
- **UNIQUE** — запрещает повторяющиеся значения
- **DEFAULT** — задаёт значение, если оно не указано
- **CHECK** — проверяет условие
- **IDENTITY** — автоматически создаёт числовые идентификаторы

## Создание базы данных CollegeDB

Для создания базы используется DDL-команда CREATE DATABASE:

```sql
CREATE DATABASE CollegeDB;
```

После создания базу необходимо выбрать для дальнейших команд:

```sql
USE CollegeDB;
```

USE определяет базу данных, в контексте которой будут выполняться последующие команды.

---

## Создание таблицы GroupInfo

```sql
CREATE TABLE GroupInfo (
    GroupID INT IDENTITY(1,1) PRIMARY KEY,
    GroupName NVARCHAR(50) NOT NULL
);
```

GroupID — идентификатор группы. INT задаёт целочисленный тип, IDENTITY(1,1) автоматически генерирует значения, PRIMARY KEY делает идентификатор уникальным.

GroupName хранит название группы, NVARCHAR(50) допускает Unicode-текст до 50 символов, NOT NULL делает значение обязательным.

---

## Создание связанной таблицы Student

```sql
CREATE TABLE Student (
    StudentID INT IDENTITY(1,1) PRIMARY KEY,
    FirstName NVARCHAR(50) NOT NULL,
    LastName NVARCHAR(50) NOT NULL,
    GroupID INT FOREIGN KEY REFERENCES GroupInfo(GroupID)
);
```

GroupID в Student — внешний ключ. Он ссылается на GroupInfo.GroupID и реализует связь "одна группа — много студентов".

---

## Порядок создания таблиц

Таблица, на которую ссылается внешний ключ, должна существовать раньше таблицы, содержащей этот внешний ключ. В нашем случае сначала создаётся GroupInfo, затем Student.

Это связано с зависимостью объектов: Student.GroupID должен ссылаться на существующий GroupInfo.GroupID. То же правило применяется при заполнении данных: сначала создаются родительские записи, затем зависимые.

---

## Команда INSERT

INSERT относится к DML — языку манипулирования данными. Команда INSERT добавляет новые строки в таблицу.

Рекомендуется явно указывать список столбцов:

```sql
INSERT INTO Student (FirstName, LastName)
VALUES (N'Иван', N'Иванов');
```

Список столбцов делает запрос понятнее и устойчивее к изменениям структуры таблицы.

---

## Сопоставление столбцов и значений

Порядок значений в VALUES должен соответствовать порядку столбцов в списке INSERT.

В запросе:

```sql
INSERT INTO Student (FirstName, LastName)
VALUES (N'Иван', N'Иванов');
```

получается соответствие: FirstName ← Иван, LastName ← Иванов. Количество значений должно совпадать с количеством указанных столбцов.

---

## IDENTITY, DEFAULT и NULL при INSERT

INSERT не обязан передавать значение для каждого столбца.

- IDENTITY генерирует значение автоматически
- Если столбец допускает NULL, его можно не указывать или явно передать NULL
- Если столбец имеет DEFAULT, при отсутствии значения SQL Server подставляет значение по умолчанию
- Если столбец NOT NULL не имеет DEFAULT и значение не передано, вставка завершится ошибкой

---

## DEFAULT при INSERT

DEFAULT применяется, когда значение для столбца вообще не задано.

Например:

```sql
IsActive BIT NOT NULL DEFAULT 1
```

Если выполнить INSERT без IsActive, SQL Server установит IsActive = 1. Если явно передать NULL, DEFAULT не применяется. При NOT NULL такая вставка будет отклонена.

---

## Вставка нескольких строк

Одна команда INSERT может добавить сразу несколько строк:

```sql
INSERT INTO Student (FirstName, LastName)
VALUES 
    (N'Иван', N'Иванов'),
    (N'Петр', N'Петров'),
    (N'Мария', N'Сидорова');
```

Каждая пара VALUES соответствует отдельной строке. Такой способ удобнее, чем отдельный INSERT для каждой записи.

---

## Заполнение связанных таблиц

Сначала добавляются записи в родительскую таблицу GroupInfo:

```sql
INSERT INTO GroupInfo (GroupName)
VALUES (N'ИС-101'), (N'ИС-102');
```

После этого добавляются студенты, которые ссылаются на существующие группы:

```sql
INSERT INTO Student (FirstName, LastName, GroupID)
VALUES 
    (N'Иван', N'Иванов', 1),
    (N'Петр', N'Петров', 1),
    (N'Мария', N'Сидорова', 2);
```

Так сохраняется ссылочная целостность.

---

## Нарушение ограничений

SQL Server проверяет данные перед добавлением строки:

- PRIMARY KEY не допускает повторного значения ключа
- UNIQUE не допускает повторяющегося уникального значения
- NOT NULL требует обязательного значения
- CHECK требует выполнения заданного условия
- FOREIGN KEY требует существования связанной записи в родительской таблице

Если правило нарушено, операция INSERT отклоняется.

---

## Команда SELECT

SELECT используется для получения данных из таблицы:

```sql
SELECT * FROM Student;
```

Можно выбрать конкретные столбцы:

```sql
SELECT FirstName, LastName FROM Student;
```

Или добавить условия:

```sql
SELECT * FROM Student WHERE GroupID = 1;
```

---

## Проверка INSERT

Упрощённо операцию можно представить так:

INSERT → проверка структуры команды → проверка типов данных → проверка NOT NULL → проверка PRIMARY KEY → проверка UNIQUE → проверка CHECK → проверка FOREIGN KEY → добавление строки.

По сути, INSERT — это не просто запись значений: SQL Server одновременно контролирует правила целостности, заданные структурой таблицы.
